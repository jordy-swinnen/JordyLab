# Contract: Machine Connect (browser sign-in + loopback callback)

New. Backend: second OAuth public client on the existing authorization server (spec 021 pattern). Serves US1.1 / FR-002, ticket D4.

## Flow

1. App shows **Connect this PC** (design `D_Connect.png`) with a **Sign in** action.
2. App opens the system browser at the JordyLab login with an authorization request:
   - `client_id=jordylab-desktop-app` (public client, PKCE S256)
   - `redirect_uri=http://127.0.0.1:19878/callback` (fixed; 19877/19876 belong to the MCP clients)
   - `scope=machine.connect` (admin-only gate server-side)
   - PKCE `code_challenge` + random `state` generated by the app
3. The user signs in with the admin account (password or passkey — existing identity flows).
4. The authorization server validates admin role, then redirects to the loopback callback with `code` + `state`.
5. The app exchanges the code (PKCE verifier) at the token endpoint and receives the machine's **`jlmt_` token**.
6. The app stores the token in `~/.config/jordylab/scan/token.json` (mode 0600, existing cache path) and appears in Settings → Machines.

## Rules

- Non-admin accounts: the authorization server refuses with a clear error; the app shows the permission-denied state (design: described in design system's desktop section).
- `state` mismatch or callback timeout: the app shows the failure and offers retry; nothing is stored.
- Machine identity resolution stays server-side: `(machine_id, sourceType)` with `(hostname, sourceType)` fallback — unchanged.
- Token revocation in Settings → Machines is detected on the next check (`401`/`403`) → app shows "needs reconnection" (US1 edge case).

## Error surface (app window)

| Condition | Message |
|-----------|---------|
| Non-admin sign-in | "Only the admin account can connect a machine." |
| Callback timeout | "Sign-in did not complete. Try again." |
| Token rejected later | "This machine must be reconnected." |
