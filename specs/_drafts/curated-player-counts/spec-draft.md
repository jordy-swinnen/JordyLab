# Feature Draft: Hand-set player counts for games no source covers

**Status**: Draft, ready for specification once the second-source player-counts draft is specified (this one builds on its separate count-source field)
**Target path**: `specs/_drafts/curated-player-counts/spec.md`
**Amends**: the game detail page and admin tools of the game catalog, the fill-only rule in `Game` for `max_local_players`, the "player count isn't known yet" note LibBot adds to party-size answers, and the Sources page backlog explanation

> Follow-up to `specs/_drafts/multiplayer-player-counts/`. That draft adds a second source for console games and measured the alternatives; what it leaves unknown is the scope here.

## Problem

After the second source is in, two groups of local-multiplayer games still have no usable player count:

- **Steam PC games** (29 at the time of the check, for example Boomerang Fu, PICO PARK, Move or Die, SpeedRunners). Steam's categories say a game is local multiplayer but never how many players. IGDB has no rows for many of them, and no source tried was reliable: TheGamesDB's single "players" number does not say whether it counts local or online players (9 of 24 matches said 1 player for a game Steam calls local multiplayer; others looked like online limits, such as 12 and 20), and Wikidata had a maximum for 2 of 29.
- **Console games where a source is wrong or sources disagree** (for example Mario Party 7, where one source says 7, 7 and 4, or PlayStation All-Stars Battle Royale, where entries say 4 and 2). The second-source draft deliberately stores nothing in that case, so they stay unknown.

For a library this size the owner knows these numbers. The party-size question LibBot answers is only as good as the counts, and "unknown" for a game the owner can answer in a second is the worst outcome left.

## Requirements

Priorities: High, Medium, Low.

- **High**: An admin can set one number of local players for any game from the game detail page, and clear it again. Nobody else can.
- **High**: A hand-set count is never overwritten by any source, scan, sweep or bulk "Refresh game data" run, and it wins over a source value. Clearing it returns the game to the normal derivation, which fills it from a source if one has a count.
- **High**: A hand-set count is distinguishable from a source count: the game keeps a marker that the count was set by hand, who set it and when. The detail page says "set by you" where it names the source today, and LibBot's citations can say so.
- **High**: LibBot treats a hand-set count as a confirmed count. It no longer counts the game among those whose player count isn't known.
- **High**: The value is validated: a whole number from 2 to the same upper bound the catalog already allows. The control is offered only for games flagged local multiplayer, and it never changes the flags, so a number cannot contradict them.
- **Medium**: The list of games still without a count (the numbers behind the Sources page) links each game to its detail page, and offers a quick way to enter a count for the games listed without opening each one, since the Steam games come in dozens.
- **Medium**: The Sources page counts hand-set values next to the source counts, so the owner sees how many games rest on their own entry.
- **Medium**: Where a source later disagrees with a hand-set value, the detail page shows the source's value as information and keeps the hand-set one. Nothing is changed automatically.
- **Low**: Setting or clearing a count is not logged anywhere beyond the marker above (who and when). The catalog keeps no admin audit trail, only created and modified dates, and this draft does not add one.
- **Low**: A one-time research step looks for a reliable source of local player counts for PC games, using only access the service grants and the same measured-table approach as the console source. If one is found it is a separate draft; this one does not wait for it.

## Success criteria

- The owner can enter counts for the 29 Steam games and the console games left unknown in under 15 minutes, and a party-size LibBot question then names no game as unknown that has a hand-set count.
- A bulk "Refresh game data" run and an automatic sweep leave every hand-set count unchanged, verified on a copy of the real library.
- A hand-set count shows "set by you" with the date; clearing it removes the marker and lets a source fill the game on the next refresh.
- A guest or any non-admin account cannot set, change or clear a count (the request is refused, the control is not shown).
- No count exists in the database without either a source's own field or the owner's entry.

## Out of scope

- Having an AI estimate or extract counts. A hand-set count is the owner's own entry, never a suggestion generated by a model.
- Per-person or per-console counts, online or co-op player limits, accessories.
- Editing the local-multiplayer or split-screen flags themselves; that stays with the existing derivation.
- Importing counts from a file or from another service in bulk.

## Open items

- **Marker design (planning)**: whether "set by hand" is a new source value for the count or its own field. It follows from how the count's source is stored in the second-source draft, so it is settled when that draft is planned.
- **Quick entry (planning)**: an inline number box in the missing-counts list versus a small dialog per game; either satisfies the requirement, the choice is a layout one.
- **Lower bound**: this draft says 2, because 1 contradicts a local-multiplayer flag. A game whose flag is wrong is a flag problem and is handled outside this draft, not by recording a count of 1.

## Verified in the repo

- Nothing in the catalog sets `max_local_players` by hand today: the API and admin UI expose no way to edit it, so a hand-set value cannot yet be told from a source value.
- The fill-only rule is in `Game` (the count is set only while it is null), so a hand-set value is safe from the fill steps already; the bulk refresh resets attempts but does not clear counts. The change that is needed is the marker and the rule that a hand-set value is never replaced by a re-derivation.
- The entity guard allows a count from 1 to 64; the API and detail page already return and show the count and its source.
- Admin-only actions in the catalog (refresh, host names, console management) use the admin role check on the controller; the new endpoint follows that pattern.
- LibBot's unknown-count note counts games whose count is null among those matching the flags; a hand-set count stops that without further change.
