# Tasks: Game Catalog

**Input**: Design documents from `/specs/002-game-catalog/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Design note**: the original plan used a Python sidecar (`gamecatalog-sync-service`) pushing to `/ingest/sync` with a static bearer token (`IngestAuthFilter`). That design was superseded (Flyway `V20260806__gamecatalog_scan_redesign.sql`). As shipped, a **shell script** generated by `ScriptService` authenticates to Keycloak via the **Device Authorization Grant** and POSTs a directory listing to `POST /api/gamecatalog/ingest/scan`; the backend parses it with a `LibraryParser` and reconciles. There is no sidecar and no static token. A checked box below means the artifact exists in the repo (and, for tests, is green); unchecked boxes are known gaps.

**Tests**: INCLUDED — entity tests are definition-of-done per `jordylab-be/AGENTS.md`; 80% coverage gates on backend (JaCoCo) and per Nx lib.

## Dependencies & Execution Order

Setup -> Foundational -> US1 (blocks nothing in the UI but produces the data) -> US2..US5 (independent of each other once the catalog has rows) -> Polish. Within a story: tests before implementation; models before services; services before controllers; api-lib stores before ui containers.
